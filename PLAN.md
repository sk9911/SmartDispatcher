## Tooling

The platforms in SPEC §2 are a **JupyterLab notebook in a desktop browser** and a **static `report.html` in current desktop Chrome**. QA drives both through a real Chrome browser using one browser-automation MCP server. Agents never install tools or edit `.mcp.json`. **You run every install yourself, in the repo root**, and T0 checks the result.

### MCP server

| Server | Why QA needs it | Configuration |
|---|---|---|
| **playwright**: Microsoft's official Playwright MCP, from `.mcp.json` | Opens the report and the JupyterLab UI in your installed Google Chrome (verified 2026-10-01: Chrome 154). Clicks (Run All, sliders, dropdowns, legends), evaluates selectors, takes screenshots, and reads console messages and network requests. | `npx -y @playwright/mcp@latest` (already in `.mcp.json`) |

Two facts about this server, both verified on 2026-10-01, shape every QA step:

- **It blocks `file://` URLs** ("Access to file: protocol is blocked"). QA therefore loads pages from a **static server** on `http://127.0.0.1:8765` that serves the repo root. The `file://` requirement in SPEC §2 is tested by T30's pytest-playwright suite, which has no such block.
- **`browser_snapshot` returns an accessibility tree.** It shows text and roles but not ids, classes, inline styles or `data-*` attributes. Every structural assertion (`#fig-… .main-svg`, output MIME types, legend opacity, colour-bar titles, hover text) uses **`browser_evaluate`** with a DOM selector.

## Rules for this plan

- **Line format:** `status | ID | title | deps | owns | check`. Every task depends on T0. `owns: —` means the task owns no files.
- **Validation:** after any edit to this file, `python3 scripts/check_plan.py` must print `OK`. It checks that every task line parses, that IDs are unique, that every dependency exists, that every task depends on T0, that there are no cycles and no dependencies already implied by other dependencies, and that no two tasks that can run at the same time own overlapping files.
- **Status:** `[todo]`, `[doing]`, `[done]` or `[blocked]`. Only the lead edits this file: teammates report to the lead, and the lead updates the status.
- **Dependencies** list only what a task really needs: code it imports, data it reads, or a contract it implements. Code that follows a contract can start once `docs/CONTRACTS.md` (T2) exists, without waiting for the code it will later be wired to. Optional (N) and stretch (S) tasks also depend on the last task they must not disturb, so a finished QA is never invalidated.
- **Ownership:** a task creates or edits only the files it owns; it may read or import anything. Tasks that can run at the same time never own the same file. `pyproject.toml` and `uv.lock` belong to T1. If a later task needs a new dependency, it goes to `[blocked]` and T1 is re-opened to add it.
- **CLI:** `src/regret/cli.py` (T1) dispatches `regret <cmd>` to `regret.<cmd>.main` with `importlib`, so a module's file name *is* its command. The reserved commands are `fetch`, `compute`, `report`, `ensemble` and `geostrophic`. Later tasks add `main()` to their own module and never edit `cli.py`.
- **Datasets:** `src/regret/config.py` (T4) lists every WeatherBench 2 dataset in SPEC §3.1: the core ones, plus the optional `neuralgcm` and the stretch `neuralgcm_ens` and `geopotential`. `regret fetch` fetches the core datasets and takes `--with <name,…>` for the others, so no later task edits `fetch.py`.
- **Figures** each live in their own module under `src/regret/figures/`, which exports `FIG_ID` and one `build_*` function returning a `go.Figure`. HTML is always made with `fig.to_html(div_id=FIG_ID, …)`, never `fig.show()`, so ids are stable; the notebook loads plotly.js once, inline. Only T28b (and later S3) edit the notebook.
- **Fidelity over speed:** never reduce the planner grid, the replay step, the sample or the bootstrap to meet a time limit. If a check's time limit is missed, make the code faster or run it in parallel; if that fails, mark the task `[blocked]` with the measured time.
- **Long commands** (T9, T17, the full runs in T32 and N1) run with `run_in_background`, because a foreground command stops after 10 minutes.
- **QA tasks** follow every feature a user sees in a browser. Each owns `qa/<ID>/`: findings go in `qa/<ID>/report.md`, screenshots in `qa/<ID>/*.png` (both committed), scratch files in `qa/<ID>/scratch/` (gitignored). They fix nothing. A failure is listed in the report and sent to the lead, who adds a bug-fix task (see *Bug-fix tasks*). CLI commands are checked by their own tasks, since no Tooling server drives a terminal.
- **Bug-fix tasks** are added by the lead as `B<n>`: deps are the QA task that found the bug; owns are the feature task's files; check is the feature task's check plus the failed QA step, re-run by `qa-tester`. The lead also adds `B<n>` to the deps of every task that depends on that QA task.

### Shared runtime resources

- **JupyterLab** runs on port 8888. A task starts it with `REGRET_BLOCK_NETWORK=1 REGRET_CONFIG=fixture uv run jupyter lab --no-browser --ip 127.0.0.1 --port 8888 --IdentityProvider.token regret-dev` (background; kernels inherit both variables) only if `curl -sf -H "Authorization: token regret-dev" http://127.0.0.1:8888/api/status` fails, and stops it when the task finishes. A check on the full config (T32) stops any running JupyterLab and starts it with `REGRET_CONFIG=full` instead.
- **Notebooks in JupyterLab:** QA never opens a tracked notebook. It copies it to `qa/<ID>/scratch/` and opens the copy (JupyterLab autosaves every 120 s, which writes outputs into the file). Every QA task ends with `git status --porcelain -- notebooks/` empty.
- **Static server** runs on port 8765 and serves the repo root. A task starts it with `uv run python -m http.server 8765 --bind 127.0.0.1` (before T1 exists, `python3 -m http.server 8765 --bind 127.0.0.1`) in the background only if `curl -sf http://127.0.0.1:8765/ >/dev/null` fails, and stops it when the task finishes.

### Standard checks

- **Standard browser check (SBC)** for page *P* (a path under the repo root) and figure IDs *F*, in `playwright`:
  1. Make sure the static server is running, then `browser_navigate` to `http://127.0.0.1:8765/<P>`.
  2. `browser_evaluate` confirms that for each id in *F*, `document.querySelectorAll('#<id> .main-svg').length >= 1`.
  3. `browser_console_messages` has 0 messages at level `error`, with one allowed exception: a single 404 for `/favicon.ico` (the static server has none).
  4. `browser_network_requests` lists no URL outside `http://127.0.0.1:8765/` and `data:`.
  5. `browser_take_screenshot` is saved to `qa/<ID>/chrome.png`.
- **Standard notebook check (SNC)** for builder *B*:
  1. Write `qa/<ID>/scratch/check.ipynb`. Its first code cell calls `regret.offline.install_if_requested()`; the next calls *B* (on `tests/fixture_results/regret.parquet`, or on the fixture config for `build_showcase_map`) and displays the figure.
  2. Make sure JupyterLab is running. In `playwright`, open `http://127.0.0.1:8888/lab/tree/qa/<ID>/scratch/check.ipynb?token=regret-dev`, then choose menu Run → Run All Cells.
  3. `browser_evaluate` confirms: at least one `.jp-OutputArea .js-plotly-plot`; 0 elements matching `[data-mime-type="application/vnd.jupyter.stderr"]`; and the status bar text contains `Idle`.
  4. `browser_take_screenshot` is saved to `qa/<ID>/notebook.png`.
- **Plotly interactions:** if `browser_hover` or `browser_click` on a Plotly element is intercepted (Plotly's drag layer sits on top) or has no snapshot ref, use a real `page.mouse.move`/`click` via `browser_run_code_unsafe`, or trigger it with `browser_evaluate` (e.g. `Plotly.Fx.hover` or a dispatched `click` event on the slider step or legend item) and note that in `qa/<ID>/report.md`.
- **Overlap sweep:** use `querySelectorAll` (never a single-match selector, which only finds the first axis) on `text[class$="title"]` (covers `xtitle`, `x2title`, `y3title`, `gtitle`, `cbtitle`), `.annotation`, `.legend` and its items, `.updatemenu-container`, `.slider-container`, `.colorbar` and tick labels of every subplot; compare `getBoundingClientRect` pairwise, excluding parent/child pairs and tick-to-tick pairs on the same axis.
- **Fits container:** at the target width, each figure's `.main-svg` width is ≤ its output container's `clientWidth` (the overlap sweep cannot catch clipping).
- **Figure page** for a QA task: `qa/<ID>/scratch/fig.html`, written in `check.ipynb` by `fig.write_html(path, include_plotlyjs=True, div_id=FIG_ID)`; for the showcase map, use `showcase_map.write_html(fig, path)` (B4), which also inlines the basemap.

## Scheduling

The current order of runnable work is printed by `python3 scripts/check_plan.py --waves`, which groups unfinished tasks into waves: every task in a wave has all its deps in earlier waves. Within that order:

- **At most 3 tasks** are `[doing]` at once (CLAUDE.md).
- **Browser tasks** use the `playwright` server and run one at a time: T0, T1 and every QA task (T19, T21, T23, T25, T27, T29, T32, N2, S4, and any `B<n>`).
- **Exclusive tasks** run with nothing else `[doing]`, because they load every CPU core or time the whole pipeline: T17, T32, N1, N2.
- **Timed tasks** (T11, T15, T20, T28b, T30) never run while T9 or an exclusive task is `[doing]`, so their time limits measure the code, not contention.
- **Priority** when more tasks are runnable than slots: the earliest wave first; within a wave, tasks on the path to T8 first (T8 is the first contact with the live stores, so a data problem surfaces early), then core before optional (N) before stretch (S).
